01: Foundations - What Are We Drawing?

Before diving into code, let's understand what we're trying to achieve. The goal of three-edge-projection is to convert a 3D model into a 2D line drawing, like an architectural blueprint or technical illustration.

The Problem: 3D → 2D

A 3D mesh is made of triangles. When we look at it from above (orthographic projection), we don't want to draw every triangle edge - that would be a mess. Instead, we want to draw only the meaningful edges:

All Triangle Edges

___________ /\ /\ /\ / \ / \ / \ /____\/____\/____\ \ /\ /\ / \ / \ / \ / \/____\/____\/ Too many lines - hard to read!

Meaningful Edges Only

___________ | | | | |___________| Clean and readable!

Two Types of Important Edges

1. Hard Edges (Angle-Based)

A hard edge is where two faces meet at a sharp angle. Think of the corner of a box - the faces meet at 90°, creating a visible crease.

The library uses an angleThreshold (default: 50°) to decide what counts as "sharp enough". If the angle between face normals exceeds this threshold, the edge is drawn. 

// The math: compare face normals
const dotProduct = normalA.dot(normalB);
const angle = Math.acos(dotProduct);  // in radians

// If angle > threshold, it's a hard edge
if (angle > angleThreshold) {
    // Draw this edge!
}

2. Silhouette Edges (View-Dependent)

A silhouette edge is where the surface "turns away" from the viewer. One face points toward the camera, the other points away. These edges define the outline of the object.

Top-Down Projection (looking down Y axis): Camera/Projection Direction ↓ ↓ ┌─────────┴─────────┐ │ VISIBLE │ │ (facing up) │ ├───────────────────┤ ← Silhouette Edge! │ HIDDEN │ │ (facing down) │ └───────────────────┘ The edge between visible and hidden faces = silhouette

To detect silhouettes, we check if the two faces are on opposite sides of the projection plane: 

// projectionDir is typically (0, -1, 0) for top-down
const dotA = normalA.dot(projectionDir);
const dotB = normalB.dot(projectionDir);

// If signs differ, faces point in opposite directions
if (Math.sign(dotA) !== Math.sign(dotB)) {
    // This is a silhouette edge!
}

Key Insight

An edge is drawn if it's either a hard edge (sharp angle) or a silhouette edge (outline). Many edges are both! The corner of a box viewed from an angle is both sharp AND an outline.

Visible vs Hidden Lines

Once we know which edges to draw, we need to figure out which parts are visible (in front of everything) and which are hidden (obscured by geometry).

Side View: ┌───────┐ │ │ Box in front ────────────────┼───────┼──────────────── Edge we're testing │ │ └───────┘ Top View: ════════════════╬═══════╬════════════════ visible hidden visible Result: Three line segments - Left segment: VISIBLE - Middle segment: HIDDEN (behind box) - Right segment: VISIBLE

This is the most computationally expensive part of the algorithm. For every edge, we need to check every triangle that might be in front of it. This is where BVH (Bounding Volume Hierarchy) acceleration becomes essential.

What is a BVH?

A Bounding Volume Hierarchy is a tree structure that groups nearby geometry together. Instead of checking every edge against every triangle (O(n²) complexity), we can quickly skip large groups of triangles that are nowhere near our edge.

Without BVH: With BVH: Check edge against: Check edge against: - Triangle 1 ✗ - Root box: intersects? YES - Triangle 2 ✗ - Left half: intersects? NO → skip 500 triangles! - Triangle 3 ✗ - Right half: intersects? YES - Triangle 4 ✗ - Check only nearby triangles - ... - Triangle 1000 ✗ Result: Check ~20 triangles instead of 1000 O(n²) = 1,000,000 checks O(n log n) = ~10,000 checks

The library uses BVH in two places:

  • three-mesh-bvh: For accelerating triangle intersection queries
  • LineObjectsBVH: A custom BVH for the extracted edges themselves

Key Configuration Options

const generator = new ProjectionGenerator();

// How sharp an angle must be to create a hard edge
generator.angleThreshold = 50 * Math.PI / 180;  // 50 degrees (default)

// Whether to detect intersection edges
generator.includeIntersectionEdges = true;  // default

// Time budget per iteration (for responsive UI)
generator.iterationTime = 30;  // 30ms default
