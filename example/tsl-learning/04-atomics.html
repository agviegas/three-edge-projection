TSL Learning 04: Atomic Operations

When multiple GPU threads need to modify the same memory location, we have a problem: race conditions. Atomic operations solve this.

The Problem

Thread 0: read counter (0) → add 1 → write (1) Thread 1: read counter (0) → add 1 → write (1) ← Problem! Both read 0! Thread 2: read counter (0) → add 1 → write (1) Expected result: 3 Actual result: 1 (or some other wrong number)

The Solution: atomicAdd

atomicAdd performs read-modify-write as a single uninterruptible operation. No other thread can access the memory until it's done.

Thread 0: atomicAdd(counter, 1) → returns 0, counter is now 1 Thread 1: atomicAdd(counter, 1) → returns 1, counter is now 2 Thread 2: atomicAdd(counter, 1) → returns 2, counter is now 3 Result: 3 ✓

Important: Atomics Work on Integers Only

WebGPU only supports atomic operations on integers (int, uint). If you need floats, you must use a workaround (multiply by a large number, use atomics, divide later).

Key Concepts

  • .toAtomic() - Marks a buffer for atomic operations
  • .setPBO(true) - Makes a buffer readable back to JavaScript
  • atomicStore(ptr, value) - Write a value atomically
  • atomicAdd(ptr, value) - Add to a value atomically (returns the old value)
  • atomicLoad(ptr) - Read a value atomically

Important: You cannot read atomic buffers directly back to JavaScript. Instead, copy the result to a non-atomic buffer using atomicLoad, then read that buffer.

The Code

import { atomicAdd, atomicStore, atomicLoad } from 'three/tsl';

// Create an atomic counter buffer
const counterBuffer = instancedArray(new Uint32Array([0]), 'uint').toAtomic();

// Create a separate buffer for reading results (non-atomic)
const resultBuffer = instancedArray(new Uint32Array([0]), 'uint').setPBO(true);

// Initialize sum to 0
const initKernel = Fn(() => {
    atomicStore(counterBuffer.element(0), uint(0));
})().compute(1);

// Sum all values
const sumKernel = Fn(() => {
    const value = inputBuffer.element(instanceIndex);
    // Atomically add this value to the total
    atomicAdd(counterBuffer.element(0), value);
})().compute(inputData.length);

// Copy result to readable buffer
const copyKernel = Fn(() => {
    const sum = atomicLoad(counterBuffer.element(0));
    resultBuffer.element(0).assign(sum);
})().compute(1);

Why This Matters for Edge Clipping

In the edge clipping problem, many triangles might overlap the same edge. We need to atomically add each overlap to an output buffer. This is exactly what atomicAdd enables!
